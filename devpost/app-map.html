TeachBack App Map

TeachBack asks you to explain AI-written code back, chunk by chunk, and paints each line by how well you understood it. There are three main pieces: pages in the browser (app/ + components/), two API routes on the Next.js server (app/api/analyze, app/api/grade) that talk to Claude or the demo grader, and pure logic in lib/ (scoring, prompt, session, storage).

One action, end to end: “Submit explanation”

Reference route (3 stops)

This is a reference route. It hasn't been toured live yet.

  1. Input: components/SessionView.tsx, search async function submit. It posts the code, the active chunk and your explanation to /api/grade. On success it calls update(recordAnswer(...)) and sets pulseId so the gutter animates.
  2. Logic: app/api/grade/route.ts validates the request with GradeBody (lib/validate.ts). With an API key it calls gradeAnswer in lib/ai.ts; otherwise, or with ?demo=1, it calls demoGrade in lib/demo.ts. Either way the score passes through applyHintCap and verdictFor in lib/scoring.ts.
  3. Result: components/CodeHeat.tsx calls lineVerdicts(), which gives each line its chunk's verdict. The line's data-state attribute then picks the colour in app/globals.css (search .code-line[data-state="owned"]).

A practice to reuse

Make the AI's output something you can check, then check it in code. The spec named one real uncertainty (spec.md › Decisions and Open Issues): would the model return reliable line ranges? The answer wasn't “trust the prompt”. It was a structured-output schema plus repairChunks() in lib/ai.ts, pinned by the test “repairChunks clamps, orders and de-overlaps model ranges” in lib/core.test.ts.

On your next project, whenever an AI response drives your UI, write down the shape you need, validate it, and add one test for the messy case.
